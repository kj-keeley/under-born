## 0. この指示書について

### この便の役割
**Kevinが検証と調整を止まらずに続けられる状態にすること。**
現在、デバッグパネルは1本の縦長で、使用頻度の高いトグル（無敵・段階・敵ゼロ・階ジャンプ）が最下部にある。値を1つ触るたびに長距離のスクロールが要る。演出中はパネルごと消えるため、演出を試す操作そのものができない。

## 1. 決定事項と理由

| 決定 | 理由 |
| --- | --- |
| デバッグパネルのグループを折りたたみ式にする | `SPEC`（L2617）が既にグループ構造を持っているのに、全項目が一列に展開されている |
| トグル群と階ジャンプをパネル最上部へ移す | 使用頻度が最も高いものが最も遠い位置にある |
| パネルをシネマティック中も表示する | 現状 L79-80 で `body.cinematic #panel` が `display:none`。演出を試すボタンがパネル内にあるため、演出中に操作できない |
| パネル自体をスクロール領域にする | 現在はページごとスクロールするため、ゲーム画面まで一緒に動く |
| 進行度を常時表示する | 50階のどこにいるか分からず、前に進んでいる感覚が失われる |
| ポーズボタンとポーズ画面を追加する | 中断できないまま50階を遊ばせることになっている |
| 常時表示は階数のみ。姿と中断はポーズ画面に畳む | 1周目の画面はボタンが実質1つしかない静かな画面で、これは資産として守る |
| **開発中はデバッグモードを既定で有効にする** | 有効化のたびに隅を5回クリックするのが摩擦になっている。開発中はONが既定で、提出前に1行戻す |
| デバッグ有効中は画面の隅に「DEV」と常時表示する | 既定ONにすると、無効化し忘れたまま配布する危険が生まれる。その印 |
| `DEV` の保存を三状態（有効／無効／既定に従う）にする | 現在の実装は無効時にキーを削除するため、既定値が `true` だと解除が効かなくなる |

## 3. 実装ステップ

### チャンク1（生存確認用・小）

#### Step 1: パネルをシネマティック中も表示する
- L79-80 の `body.cinematic ... #panel ... {display:none}` から `#panel` を除外する
- **CSSだけでは足りない。以下の3箇所がパネルを直接閉じているので、`panel.classList.remove('open')` を削除すること**
  - L2744 付近：`testEvolutionRitual`（詩を試す）
  - L2751 付近：`endingBtn.onclick`（地上演出を試す）
  - L2762 付近：階ジャンプの実行処理
  - 同じ行にある `ov.classList.remove('show')` と `setCinematic(false)` は**そのまま残すこと**。閉じるのはパネルだけをやめる
- `#panelBtn` は `#controls` の中にあるため、同じく `body.cinematic #controls` で消える。**パネルの開閉ボタンをシネマティック中も押せるようにすること。** `#controls` の外へ出す、または `#controls` 内に置いたままシネマティック時も表示する例外を設ける。方式は実装側判断でよい
- **デバッグモードが無効なときは従来どおり何も出さないこと**
- 完了条件：`?dev=1` でタイトル画面にいる状態でも「数値」ボタンが押せ、パネルが開くこと

**ここでチャンク1完了報告を出すこと。以降は報告後そのまま続行し、Kevinの返事を待たない。**

### チャンク2：デバッグパネルの再構成

#### Step 2: トグル群と階ジャンプを最上部へ
- 現在パネル最下部にあるボタン群と階ジャンプUI（L2643-2663付近）を、スライダー群より**上**に移動する
- 並び順は使用頻度順とする。**無敵／段階／敵ゼロ／階ジャンプ**を先頭に置き、それ以外（範囲を表示・暗闇の中も表示・真の姿デバッグ・全土地を自由選択・デバッグ保存・縦長5F・特殊階を巡回・詩を試す・地上演出を試す・進行をリセット・やり直す）を後ろに置く
- 完了条件：パネルを開いた直後、スクロールせずに無敵・段階・敵ゼロ・階ジャンプが見えること

#### Step 3: スライダー群を折りたたみ式にする
- `SPEC`（L2617）のグループ単位で開閉する。グループ見出し（`.grp`）をクリックすると、そのグループのスライダーだけが開く
- **初期状態は全グループ閉じる**
- 開閉状態は保持しなくてよい（パネルを閉じて開き直したら全閉でよい）。**その場合、パネルを開く処理の中で明示的に全グループを閉じること。** 閉じたときの状態がDOMに残る
- 開いているグループが分かる印（記号の向き、色など）を付けること
- 完了条件：パネルを開いた直後にスライダーが1本も見えず、グループ見出しをクリックするとそのグループだけ開くこと

#### Step 4: パネルを独立したスクロール領域にする
- `#panel` に高さの上限と `overflow-y:auto` を与え、パネル内だけがスクロールするようにする
- **あわせて `overscroll-behavior:contain` を指定すること。** 指定しないと、パネル端まで到達したスクロールが背後のページへ連鎖する
- 高さの上限は画面の6〜7割を目安とする。具体値は実装側判断でよい
- 完了条件：パネル内をスクロールしてもゲーム画面が動かないこと

### チャンク3：進行の見える化

#### Step 5: 進行度の常時表示
- プレイ中、画面に**現在階と総階数**を常時表示する（例：`18 / 50`）
- 表示場所は `#status`（L88、現在「潜伏中」を出している領域）の並びが自然。方式は実装側判断でよい
- **文字は小さく、控えめな色にすること。** 暗い画面を壊さないこと
- 演出中（シネマティック中）は従来どおり隠れてよい
- 完了条件：遺跡18階にいるとき `18 / 50` に相当する表示が出ていること。沼にいるときは分母が38になること

#### Step 6: ポーズボタンとポーズ画面
- プレイ中の操作列（`#controls`）に**ポーズボタン**を追加する
- 押すとゲームが停止し、ポーズ画面を表示する。表示する内容は以下
  - **進行度**（例：`遺跡 18 / 50`）
  - **現在の姿**（`STAGE_NAMES`（L352）を使う。ベイビー／チャイルド／ロード）
  - **再開**ボタン
  - **中断してタイトルへ**ボタン
- **セーブは行わない。** 「中断してタイトルへ」はタイトルに戻るだけで、その土地の攻略は失われる。**その旨をポーズ画面に明記すること**（例：「この階の攻略は失われます」）
- **ポーズ中の入力停止を、モードの追加だけで済ませないこと。** 既存のキー・ポインター処理は `mode` と独立に動く。特にポーズ中にキーを離すと `releaseBreath()` が走り、息止めの状態とクールタイムが変化する
  - ポーズ開始時に、移動キーの押下状態と長押し判定を解除する
  - ポーズ中はステージ、息止め、地図、真の姿の入力を一切受け付けない
  - ポーズ中にキーやポインターを離しても、息止めタイマーとクールタイムを変更しない
  - **息を止めた状態でポーズした場合の扱い（確定）**：ポーズ中はタイマーを一切動かさない。キーを離した事実だけを保留し、**再開した瞬間に息止めを解除して、そこからクールタイムを開始する**。ポーズで息を延ばせないこと、および再開後に「押していないのに止まったまま」にならないことの両方を満たす
  - 再開時に、ポーズしていた間の経過時間を流し込まない（`last` を現在時刻へリセットする）
- ポーズ中は敵・配下・タイマー類がすべて停止すること
- 「中断してタイトルへ」を押したときは、その土地の一時的な攻略状態（階・ハート・祭壇・配下）を破棄すること
- 完了条件：3階の途中でポーズを押すと敵が止まり、進行度と姿が表示され、再開すると同じ状態から続行できること。**息を止めた状態でポーズし、その間にキーを離してから再開すると、その瞬間に息止めが解除されてクールタイムが始まること。ポーズしていた時間ぶん息が延びていないこと**

#### Step 7: デバッグモードを既定で有効にする
- `DEV` の判定（L105-108付近）に**既定値の定数 `DEV_DEFAULT`** を導入し、開発中は `true` にする
- **localStorageの保存を三状態にすること。** 現在の `setPersistentDev`（L109-）は無効時に `removeItem` しており（L112）、既定値が `true` だと「解除→再読み込み→また有効」になって**解除ボタンが機能しなくなる**
  - `"1"` = 有効を保存
  - `"0"` = 無効を保存
  - **キーなし** = `DEV_DEFAULT` に従う
- 判定順は次のとおり
  1. `?dev=0` があれば無効
  2. `?dev=1` があれば有効
  3. 保存値が `"0"` または `"1"` ならそれに従う
  4. どれもなければ `DEV_DEFAULT`
- **隠し5タップは、保存値ではなく現在の実効状態 `DEV` を反転させること。** 現在の実装（L2542 `const enabled=!persistentDev;`）は保存値だけを反転しているため、既定ON・保存値なしの状態では `persistentDev` が false のまま。5タップしても `"1"` を保存するだけで、**ONのままになる**
  - URL指定なし・保存値なし・`DEV_DEFAULT=true` の状態で5タップすると `"0"` を保存してOFFになること
  - もう一度5タップすると `"1"` を保存してONになること
- **「デバッグ保存を解除」も三状態に対応させること。** 解除は「キーを消す」ではなく「`"0"` を保存する」動作になる。既定値に戻す第三の操作が要るかは実装側判断でよい
- **デバッグが有効な間、画面の隅に小さく `DEV` と常時表示する。** 固定配置とし、他のUIより高い `z-index` を与えて、タイトル・詩・進化儀式・ポーズ中のいずれでも消えないこと。無効時は出さない
- `DEV_DEFAULT` は、**1行変えるだけで配布用に切り替えられる形**にし、その旨をコード内のコメントに明記すること
- 完了条件：`?dev=1` を付けずにファイルを開いてもデバッグパネルが使えること。`?dev=0` を付けると何も出ないこと。**「デバッグ保存を解除」を押して再読み込みしても無効のままであること**。`DEV` 表示がタイトル・詩・ポーズのいずれでも見えていること

## 4. 便全体の完了条件

### 主検証

**URLに何も付けずに開き、既定でDEVが有効な状態から開始する。タイトル画面から一度もパネルを見失わずに**以下を通せること。

1. タイトルでパネルを開き、階ジャンプで遺跡17階へ飛ぶ
2. 18階へ上がり、進化儀式と詩を確認する
3. その間、画面に `18 / 50` に相当する進行度が出ている
4. ポーズを押し、進行度と姿「チャイルド」が表示される
5. 再開して続行できる

### 別テスト

`?dev=0` を付けて開き、以下がすべて出ないこと。

- `DEV` 表示
- 「数値」ボタン
- デバッグパネル
- ポーズ画面のデバッグ関連項目（もしあれば）

さらに、隠し5タップでOFFにしてから再読み込みし、URL指定なしでも無効のままであることを確認すること。

## 8. 一般配布前に戻すこと（申し送り）

この便でデバッグモードを既定ONにする。

**GitHubの `main` は開発用の作業場なので、既定ONのままでよい。** リポジトリが公開されていることは問題にしない。
**`DEV_DEFAULT` を `false` に戻すのは、itch.io への公開、評価提出、その他の一般配布用ビルドを作るときとする。**

戻し忘れると、未解禁のダンジョンとコア、真の姿、階ジャンプ、無敵がすべて初見のプレイヤーに露出する。
`TASKS.md` の提出前チェックにも同項目を追加すること。
