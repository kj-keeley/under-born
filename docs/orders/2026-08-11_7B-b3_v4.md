# UNDERBORN 実装指示：第7B-b3便 v4

> **v3→v4 差分**：追跡目標と通行不可セルの衝突を解消。`e.last`（＝マスターのマス）を通行不可にすると `bfs()` が経路を作れず、敵が距離に関係なくその場で `look` に入ってしまう。**手前の到達可能な床を目標にする**方式へ変更し、`bfs()` の共用を壊さない指定を追加。
>
> **v2→v3 差分**：`lookReason` の設定漏れと残留を防ぐため、すべての入口で理由を設定し `chase`/`patrol` でクリアする指定を追加（共通関数を推奨）／燃えた敵は**現状3秒停止していない**（`look` のタイマーが `P.search=2` のため2秒で歩き出す）ことを踏まえ、停止の実装を明示指定に変更／移動開始済みの一歩は完了を許す方針に確定／誤字と `P.search` の記述を訂正。
>
> **v1→v2 差分**：`look` が3用途で共用されているため、徘徊と `？` を「マスターを見失った場合」に限定（燃えた敵・捕縛後の敵を巻き込まない）／`chaseTimer=1.5` が新仕様を潰す件を明記／追跡対象がマスターか配下かを記録する指定を追加／既存経路の消し込みと、次の1マス開始直前の拒否を追加／`P.search` は既存スライダーの変更であると訂正／マスターのマスを避ける条件を `breathHeld && !spotted` に確定。

### この便の役割
息を止めたとき、敵が**マスターのマスまで来ずに、その手前で見失って周囲を探し、巡回へ戻る**ようにする。

現在、`chase` 状態の追跡目標は `spotted` が真の間マスターの現在地であり（L1186）、息を止めて `spotted` が偽になっても `e.last` が自分の今いる位置であるため、敵はそのまま歩いてきて到着する。**息止めは捕まるまでの遅延にしかなっておらず、移動比率0では確実に捕まる。**

### 壊すな指定
- 光と息止めのロジック（半径、点火可否、段階倍率、`breathMoveRate`）
- 7A〜7B-b2 で実装した内容
- 種火連鎖、マップ生成、**発見の判定式そのもの**（`seesMaster` / `inArc` / `los`）
- 巡回（`patrol`）と巡回路への復帰（`_returning`）の仕組み
- 配下がらみの追跡（`seesMinion` 経由の `chase`）は今回の対象外だが、壊さないこと
- **`look` 状態の他の用途を壊さないこと。** `look` は3箇所から使われている
  - L1120：真の姿で燃えた敵（`burnT`・`stallTimer` で3秒停止し、`炎` マークを出す）
  - L1253：マスターが捕まった後
  - L1191ほか：マスターや配下を見失ったとき
  この便で追加する徘徊と `？` は、**マスターを見失った場合のみ**に適用すること

## 1. 決定事項と理由

| 決定 | 理由 |
| --- | --- |
| 息を止めて見失ったとき、敵は**マスターのマスへ到達する前に `look` へ移る** | 現在は `e.last` が自分の今いる位置になるため、必ず到着する。息止めが遅延にしかならない |
| `look` 中の敵は、その場で回るだけでなく**周囲を短く徘徊する**。ただし**マスターを見失った場合に限る** | 「？を出して、あたりをうろついて、元来た道を戻る」という手触りにする。`look` は燃えた敵と捕縛後の敵にも使われており、一律に徘徊させると停止しているはずの敵が歩き出す |
| **息止め中かつ見えていないとき（`breathHeld && !spotted`）、敵はマスターのいるマスに進入しない** | 徘徊の結果として偶然踏まれると、見失った意味が消える。ただし敵の松明や外部光の中では息止め中でも `seesMaster()` が真になりうるため、**見えている場合は従来どおり進入できる**。光の下に隠れても無駄であることは設計として正しい |
| 息止めの持続（`breathMax`）と捜索時間（`P.search`）の関係が、この仕組みの本体になる | 捜索が息より長ければ、息が切れて再発見される。動けないなら「息が続く間にやり過ごせるか」の勝負になる。**これがかくれんぼの本体** |
| `P.search` のスライダーの調整範囲と名称を改める | 既に調整可能だが、最小値が1で用途の分かる名称でもない。上記の関係をKevinが実プレイで詰められるようにする |
| `look` に入る理由をすべての入口で設定し、抜けるときにクリアする | 理由が残留すると、後で燃焼や捕縛の `look` に入ったときに古い理由で徘徊する |
| **燃えた敵の停止を、この便で正しく実装する** | 現状 `stallTimer=3` だが `look` のタイマーは `P.search=2` のため、2秒で `patrol` に戻って歩き出す。`eStall`（L1089）は `spotted` の判定を止めるだけで移動を止めていない。**「3秒停止している」という既存挙動は存在しない** |
| 移動を開始済みの一歩は完了を許す | `advance()` は1マス移動の開始時点で `tx/ty` を更新するため、途中で取り消すと見た目が前のマスへ飛ぶ |
| マスター喪失時の追跡目標を、`e.last` そのものではなく**その手前の到達可能な床**にする | `e.last` はマスターのいるマスであり、Step 3 でそこを通行不可にする。目標が通行不可だと `bfs()`（L485 で `isWall(gx,gy)` なら即 `null`）が経路を返さず、L1192 の分岐で**距離に関係なくその場で `look`** に入ってしまう |

## 2. 棄却した案

**再提案しないこと。**

| 案 | 棄却理由 |
| --- | --- |
| 見つかった後は息止めが効かないと割り切る（現状維持） | 息止めが捕まるまでの遅延にしかならない。隠れる手段が存在しないことになる |
| 息止め中は敵とマスターが物理的に重ならないようにするだけ | 敵が真上に立ち続けるので、見失った感じが出ない |
| 見失った瞬間に敵が即座に巡回へ戻る | 探す時間がないと、息止めが万能の脱出手段になる |
| 息止め中は無条件でマスターのマスへ進入させない | 外部光で照らされていて敵から見えている場合まで接触できなくなる。「光の下でも息を止めれば触れられない」という別ルールになる |
| `look` 状態を一律に徘徊化する | 燃えて停止中の敵が歩き出し、`炎` マークが `？` で上書きされる |
| 息止め開始時に、移動を開始済みの敵の一歩を取り消して前のマスへ戻す | `advance()` は移動開始時に `tx/ty` を更新済み。取り消すと表示位置が飛んで不自然になる |
| `e.last`（マスターのマス）をそのまま追跡目標にしたまま、そのマスを通行不可にする | `bfs()` が経路を返さず、敵が遠くにいてもその場で `look` に入る |
| 共用の `bfs()` を無条件に書き換えて、マスターのマスを常に通行不可にする | 配下の経路探索も同じ関数を使っている。配下がマスターのマスを通れなくなる |

## 3. 実装ステップ

### チャンク1（生存確認用・小）

#### Step 1: 追跡対象を記録し、見失ったら手前で `look` へ移る

**まず追跡対象を区別できるようにする**

- **`e.chaseTarget` を導入し、`'master'` / `'minion'` を記録すること。** `chase` に入る箇所（L1023／L1100／L1139付近）でそれぞれ設定する
- 「`spotted` も `mSeen` も偽」という条件だけでは、最後に追っていたのがマスターか配下か区別できない。**この便の変更はすべて `chaseTarget==='master'` の場合に限定する**

**`chaseTimer` の扱い**

- 現在 `chaseTimer=1.5`（L1185）があり、**見失って1.5秒経つと距離に関係なく `look` へ移り、捜索時間も固定1.5秒になる**。このままでは「2マス以内」も「捜索時間は `P.search`」も効かない
- **マスターを追跡している場合（`chaseTarget==='master'`）は、`chaseTimer` による強制遷移を使わず、下記の距離判定で `look` へ移ること。** その際 `e.timer=P.search` を設定する
- **配下を追跡している場合の既存タイマーは、そのまま維持すること**

**追跡目標の決め方（重要）**

- `e.last` はマスターのいるマスであり、Step 3 でそこを通行不可にする。**`e.last` をそのまま `goTo` の目標にしてはならない**
  - `bfs()` は L485 で `isWall(gx,gy)` なら即 `null` を返す
  - 経路が空だと L1192 の `if(e.path.length===0){ e.state='look'; ... }` により、**敵が遠くにいてもその場で `look` に入る**
- `chaseTarget==='master'` かつ `spotted` も `mSeen` も偽のとき、目標を次のように決める
  - **`e.last` の周辺から、「マスター本人のマスではない」「到達可能な床」を選び、そこを目標にする。** `e.last` から1〜2マス手前が目安
  - 候補が複数あるときの選び方（敵に近い順など）は実装側判断でよい
  - **手前の到達可能な地点が見つからない場合に限り**、その場で `look` へ移る

**距離判定**

- 上記の目標へ向かいつつ、**各マスの移動を開始する前に `e.last` までの距離を確認し、2マス以内なら `look` に入る**
  - `lookReason='lostMaster'`（後述）を設定し、`e.timer=P.search` とする
  - 距離の測り方（マンハッタン／直線）は実装側判断でよい
- 現在は `e.tx===goal[0]&&e.ty===goal[1]`（L1190）で完全一致したときのみ `look` に入る。ここを距離判定に変える
- **`spotted` が真の間は従来どおりマスターの現在地を追うこと**
- 完了条件：敵に見つかった状態で息を止めると、敵が近づいてくるが**マスターのマスには到達せず**、手前で止まって `look` に入ること。**遠く（5マス以上）で息を止めた場合、敵はその場で止まらず手前まで歩いてくること**。配下を追っている敵の挙動が変わっていないこと

**ここでチャンク1完了報告を出すこと。以降は報告後そのまま続行し、Kevinの返事を待たない。**

### チャンク2：探して、戻る

#### Step 2: `look` 中に周囲を徘徊させる（マスターを見失った場合のみ）

- **`look` は3つの用途で共用されている。** 徘徊と `？` を全体に適用してはならない
  - L1120：真の姿で燃えた敵。`burnT`・`stallTimer` で3秒停止し、`炎` マークを出す。**歩き出させてはならない**
  - L1253：マスターが捕まった後
  - 見失ったとき
- **`e.lookReason` を導入し、`'lostMaster'` のときだけ徘徊と `？` を行うこと。** 他の用途は現在の挙動（その場で見回すだけ）を維持する
- **理由の残留を防ぐこと。** 設定漏れがあると、その敵が後で燃焼や捕縛の `look` に入ったときに古い `lostMaster` が残り、燃えているのに徘徊する
  - `look` に入るすべての箇所で理由を設定する
    - マスターを見失った：`'lostMaster'`
    - 配下を見失った：`'lostMinion'`
    - 真の姿で燃えた（L1120）：`'burn'`
    - マスターを捕まえた後（L1253）：`'caught'`
  - **`chase` または `patrol` へ移るときにクリアする**
  - **`enterLook(e, reason, duration)` のような共通関数にまとめることを推奨する。** 入口が複数あるため、個別に書くと漏れる
- 現在の `look`（L1194-）は `e.path=[]` で足を止め、`e.dir` を回して見回すだけ
- **`lookReason==='lostMaster'` のときだけ、周囲を短く歩き回るようにする**
  - `e.last` の周辺（半径2〜3マス程度）のランダムな床へ、`goTo` で移動する
  - 到着したら次の地点へ。`e.timer` が尽きるまで繰り返す
  - 見回し（`e.dir` の回転）は歩いている間も続けてよい
- **`lookReason==='lostMaster'` で `look` に入った時点で `？` マークを出すこと。** 現在は `look` が**終わった**ときに `？` を出している（L1199）。Kevinの体験としては「見失った瞬間に？が出る」のが自然
  - **燃えた敵の `炎` マークを上書きしないこと**
  - `look` 終了時のマークは残してもよいし、重複するなら整理してよい。実装側判断
- タイマーが尽きたら従来どおり `patrol` に戻り、`_returning` で巡回路へ帰ること（この処理は変更しない）
- **燃えた敵の停止を正しく実装すること。** これは既存挙動の維持ではなく、**この便での修正**にあたる
  - 現状：燃焼時に `stallTimer=3` を設定するが（L1119）、`look` のタイマーは `P.search`（既定2）なので**2秒で `patrol` へ戻り、残り1秒の `stallTimer` があっても L1212 の `advance()` は動く**
  - `eStall`（L1089）は `spotted` の判定を止めるだけで、移動は止めていない
  - **`lookReason==='burn'` または `e.burnT>0` の間は、経路生成と `advance()` を行わないこと。** 炎マークもその間維持する
- 完了条件：見失った敵が `？` を出し、周囲を数秒歩き回ってから、元の巡回路へ戻っていくこと。**かつ、真の姿で敵を燃やしたとき、その敵が `炎` マークのまま3秒間その場から1マスも動かないこと**（`P.search` を1秒に下げても動かないこと）

#### Step 3: 息止め中はマスターのマスに進入させない

- **条件は `breathHeld && !spotted`。** 敵の松明や外部光の中では息止め中でも `seesMaster()`（L601）が真になりうる。**見えているときは従来どおり進入できること**
- この条件が成り立つ間、敵の経路探索と移動はマスターのいるマス（`master.tx, master.ty`）を通らないこと
- **`bfs()`（L484）は敵と配下で共用されている。無条件に書き換えないこと**
  - 敵専用の経路探索関数を用意する、または `bfs()` に**通行禁止セルを渡せる任意引数**を足す、のいずれかとする
  - **配下の経路探索は変えないこと。** 配下がマスターのマスを通れなくなる
- **`advance()`（L539）は既に作られた `e.path` をそのまま消費する。** 経路探索側だけを直しても、息止め開始前に作られた経路が残っていれば進入する
  - 経路探索でそのマスを避けることに加えて、**既存経路の次のノードがマスターのマスなら拒否し、再探索すること**
- **移動を開始済みの一歩は、完了を許すこと（確定）。** `advance()`（L539）は1マス移動を開始した瞬間に `e.tx/e.ty` を次のマスへ更新するため、敵がマスターのマスへ移動を開始した直後に息を止めた場合、「次の1マス開始前の拒否」では間に合わない
  - **その一歩は取り消さず、完了させる。** 取り消して前のマスへ戻すと表示位置が飛んで不自然になる
  - 捕縛判定は `!breathHeld` を含むため、重なっても捕まりはしない
- マスターが `breathMoveRate` 0 で動けない場合も、**息止め後に新しく**踏まれないこと
- 完了条件：`breathMoveRate` を 0 にして敵の目の前で息を止めたとき、**息を止めた後に新しく敵がマスターのマスへ進入しないこと**（`tx`/`ty` と表示位置の両方で確認）
  - **「捕縛が発生しない」を条件にしてはならない。** 捕縛判定（L1115）は既に `!breathHeld` を要求しており、息止め中は元から捕まらない。座標を直接確認すること
  - **息を止めた時点で既に移動を開始していた一歩については、完了して重なってもよい**

### チャンク3：バランス調整の手段

- **既定値は 2 のまま変更しない**
- 完了条件：スライダーで捜索時間を10秒にすると、見失った敵が10秒間探し続けること
