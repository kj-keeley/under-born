## 1. ゴール

全土地が38〜50階になり、進化と詩が階数に対する割合で発生する。遺跡50階を最初から最後まで、断面図・進化儀式・詩を含めて破綻なく通せる。あわせて1周目のプレイに未解禁要素とデバッグ機能が一切現れなくなる。

## 2. 決定事項と理由

| 決定 | 理由 |
|---|---|
| 全土地の階数を大幅に増やす（遺跡50／火山44／砂漠42／森39／沼38） | 現状は1階あたり20秒程度で10階が3〜4分。ダンジョン1本として短すぎる |
| 遺跡を最長にする（50階） | 最初の土地を一番長くする。全体としては後半ほど短くなるが、土地ごとの個別差は残す（攻略順に 50→42→44→38→39 で単調ではない）。現状の序列とは逆になるがこれで確定 |
| 進化の閾値を階数に対する**割合**（36% / 76%）で判定する | 絶対値（18階/38階）だと38階の沼で2回目の進化が最終階に来て、1階だけ最終形態で終わる。土地ごとに壊れる |
| 詩は進化と同じ契機のまま | 4階/7階の詩は進化階に紐づいている。閾値が割合になれば詩も自動で追随する。詩の本文と出現条件そのものは変えない |
| 詩と進化儀式を分離し、儀式完了→暗転→詩単独→階開始の順にする | 現状 `drawEvolution` 内で詩を描いており（L2809-2812）、演出の上に文字が乗って両方死んでいる |
| 真の姿の入手を遺跡クリア→**森クリア**に移す。使用可は**2周目から** | 1周目は隠れることしかできない旅にする |
| 真の姿の性能は**固定値**（持続20秒／CT60秒） | 解放数連動・累計参照・完成体はすべて廃止。森クリア直後に弱体化するパラドックスが仕様ごと消える |
| 真の姿は**初期コア限定** | 女神の「小さき火」の宛先は初期コア個人。覚醒コアの取り分は固有技のほう |
| 未解禁のダンジョン・コア・機能は**存在ごと非表示**。総数表示も消す | グレー表示も「1/5」も「まだ何かある」と教えてしまう |
| 周回の敵HP上昇を削除する | `difficultyHp`（L731）は `e.maxHp` に使われている（L742）が、**敵HPを減らす処理がゲーム中に一つも存在しない**（`hp-=` も `damage` も0件）。上昇が挙動に影響しない |
| タブ復帰時の時間流入を止める | スマホのロックやタブ切り替えから戻ったとき、経過時間がまとめて流れ込む。50階を通しで測る際に必ず踏む |

## 3. 棄却した案

**再提案しないこと。**

| 案 | 棄却理由 |
|---|---|
| 進化の閾値を絶対値（18階/38階）で持つ | 短い土地で最終階と重なる |
| 全土地を同じ階数にする | 土地ごとの長さの差そのものを個性として残す |
| 完成体（森クリアで初期コアが最終形態化） | 概念ごと廃止。真の姿は固定値 |
| 真の姿の性能を解放土地数・覚醒コア数に連動させる | 周回開始時に解禁数が1へ戻るため、完成直後に弱くなる |

| 未解禁要素をグレーアウトで見せる | 存在ごと非表示にする |
| 周回で敵の体力を上げる | 敵HPを減らす処理が存在しないため効果がない。新設は別の話 |

## 4. 実装ステップ

### チャンク1（生存確認用・小）

#### Step 1: 階数の差し替えと進化の割合判定
- やること：`THEMES` の `floors`（L244-252）を差し替える
  - 遺跡 10 → **50**／火山 12 → **44**／砂漠 9 → **42**／森 11 → **39**／沼 8 → **38**
- `stageForFloor`（L341）を絶対値判定から**割合判定**に変える。現行は `f => f>=7?3:f>=4?2:1`
  - 進捗率 `f / FLOORS` が **76%以上で段階3**、**36%以上で段階2**、それ未満は段階1
  - 各土地での進化階は次の通りになる。この表と一致することを確認すること

  | 土地 | 階数 | 初進化 | 2回目 |
  |---|---|---|---|
  | 遺跡 | 50 | 18 | 38 |
  | 火山 | 44 | 16 | 34 |
  | 砂漠 | 42 | 16 | 32 |
  | 森 | 39 | 15 | 30 |
  | 沼 | 38 | 14 | 29 |

  **食い違った場合は割合の式を正とする。** 上表は `f/FLOORS >= 0.36` / `>= 0.76` を満たす最小の階を計算したもの（検算用）。実装は式で書き、表は結果の確認にのみ使うこと

- `masterStage()`（L342）の `forceTrueForm` 分岐は現状のまま
- 特殊敵の出現制限「3階以降」は、階数が増えたので**割合ではなく絶対値のまま**でよい
- 完了条件：`?dev=1` の階ジャンプで遺跡の17階→18階、37階→38階でのみ進化が起き、火山の15階→16階、33階→34階でのみ起きること

#### Step 2: 進行表示の長階数対応
- やること：`drawCrossSection(xc)`（L2347〜）は階数ぶんの縦リストを描いており、`ch = skyH+8+floors*(floorH+floorGap)+6`（L2350）で高さが階数に比例する。50階では画面に収まらない
- 表示可能な高さに収める。現在地の周辺のみ描く、間隔を詰める、区切りだけ描く等、方式は実装側判断でよい。**現在いる階と残りの階数が読み取れること**が要件
- 呼び出し元は L2313（`drawXsec` が真のとき）。呼び出し側の条件は変えない
- 完了条件：遺跡50階の1階・25階・50階のいずれでも、断面図が画面内に収まり現在地が判別できること

**ここでチャンク1完了報告を出すこと。以降は報告後そのまま続行し、Kevinの返事を待たない。**

### チャンク2：詩と儀式の分離

#### Step 3: 詩表示の汎用化
- やること：現在 `mode='poem'` で開始詩のみに使われている単独表示を、任意の詩篇を受け取れる形にする。呼び出し側が「詩篇・次に進む先」を渡せばよい状態にする
- 完了条件：開始詩がこれまで通り表示され、スキップも従来通り効く

#### Step 4: 儀式から詩を引き剥がし、状態遷移を組み替える
- やること：`drawEvolution` 内の `ritualPoem` 描画（L2809-2812付近）を削除する
- **あわせて `nextFloor` の状態遷移を組み替える。** 現状は `mode='play'; buildFloor();` を先に実行してから進化判定しており（L601-612）、`startEvolution` が後から mode を上書きしている。このままだと敵紹介ズームが先に立ち上がって順序が崩れる
- 進化が起きる階では、以下の順序を**状態として保証**すること。前の段階が終わるまで次を開始しない
  1. 前の階の終了
  2. 進化儀式（`mode='evolve'`）
  3. 0.6秒の暗転
  4. 詩の単独表示（`mode='poem'`）
  5. 階の開始
  6. 敵紹介ズーム（新種がいる場合のみ）
- 進化階では敵紹介を詩の終了後まで開始させない。`buildFloor` を先に呼ぶ実装のままにするなら、紹介ズームの起動だけを遅延させる形でよい
- **詩の本文と、どの進化でどの詩が出るかの対応は変えない。** Step 1 で進化階が動くので、詩も自動的にその階へ移る
- 完了条件：遺跡18階と38階で、儀式アニメ中に文字が一切出ないこと。かつ儀式→暗転→詩→階→敵紹介、の順に必ず並ぶこと

### チャンク3：見せすぎの一掃

#### Step 5: 未解禁の完全非表示
- やること：土地選択（L2328-2334）とコア選択（L2317-2324）から、未解禁・未覚醒の項目を**DOMごと生成しない**。`.locked` クラスと `unlock-note`（「未解禁・◯◯の攻略が必要」等）も削除。攻略順の一覧表示も未解禁分は出さない
- **総数表示も削除する。** L2321 の `覚醒 ${awakenedCount()}/4　解禁土地 ${campaign.unlocked}/5` は、項目を隠しても「あと3個ある」と教えてしまう。周回レベルの表示だけ残し、`/4` `/5` の分母を消すこと
- 完了条件：進行をリセットした直後、**選択UIのDOMに**遺跡1つ・初期コア1つしか生成されていないこと（JSソース内に定数として全名称が存在するのは可）。未解禁の個数を推測できる数字が画面に出ていないこと

#### Step 6: 選択肢が1つの画面を飛ばす
- やること：選択可能な項目が1つしかない場合、その画面を表示せず自動でそれを選んで次へ進む。コア選択・土地選択の両方に適用
- 完了条件：リセット直後にタイトルから開始すると、選択画面を通らずに遺跡1階へ入ること

#### Step 7: デバッグ機能の隔離
- やること：デバッグパネルとその開閉ボタン（`panelBtn`）を、**URLに `?dev=1` が付いている時だけ**生成する。対象は数値スライダー一式と全トグル（真の姿デバッグ／全土地を自由選択／縦長5F／特殊階巡回／詩を試す／地上演出を試す／進行をリセット／やり直す）
- **DOM生成とイベント登録を必ず同じ dev 条件の中に入れること。** 現状はデバッグ部品に対して無条件に `.onclick` / `addEventListener` を設定しているため、DOMだけ消すと `null.onclick` で起動時にゲーム全体が落ちる
- **階ジャンプ機能を `?dev=1` 側に用意すること。** 50階を検品するのに1階から歩くのは現実的でない。任意の土地・任意の階へ直接入れること
- 完了条件：`?dev=1` なしで開いてコンソールにエラーが出ず、パネルもボタンも存在しないこと。`?dev=1` を付けると全機能＋階ジャンプが使えること

#### Step 8: 真の姿ボタンの非表示
- やること：メインUIの真の姿ボタン（`trueBtn2`, L97）を、`trueFormUnlocked` が false の間は**DOMごと非表示**にする。「真の姿 未覚醒」の表示は廃止
- 完了条件：1周目のプレイ中、真の姿という語がUIのどこにも出ないこと

### チャンク5：周回スケーリングと時間バグ

#### Step 14: 周回スケーリングの修正
- やること：`difficultyHp`（L731）と、それを使う `e.maxHp` の倍率適用（L742）を削除し、`e.maxHp=P.eHp` に戻す。敵数を `baseEnemyCount + (campaign.loopLevel - 1)`（毎レベル+1）に変更。周回ダイヤルの説明文（L2246）を「敵の数と速度が上がります。」に変更
- 完了条件：Lv1とLv2で敵数が1体違うこと。説明文に「体力」の語が残っていないこと

#### Step 15: タブ復帰時の時間流入を止める
- **`dt` の上限は既にある。** L2858 の `dt=Math.min(0.05,(now-last)/1000)` はそのまま維持し、値も変えないこと
- 足りないのは `visibilitychange` の処理で、これは現在存在しない。**非表示から復帰したとき `last` を現在時刻へリセットし、隠れていた間の時間を完全に破棄すること**
- 上限0.05秒があるため1フレーム分の飛びは既に抑えられているが、復帰時に `last` が古いままだと最初の1フレームが必ず上限値を消費する。長時間のロック後もこれを0にするのが目的
- 完了条件：プレイ中にタブを裏に回して1分待ち、戻ったとき息止めのクールタイムと配下の数が離脱前と同じであること

## 9. 出力形式の指定

- **差分で出力する。** 全文は最終確認時に一度だけ
- チャンク内は自走し、**チャンク完了時のみ報告**。ただしチャンク1完了時は生存確認として必ず応答すること
- チャンク1の報告後は、Kevinの返事を待たずチャンク2以降へ続行すること
- 完了報告は**反映／見送り／質問**の3区分で書く
- 指示書と実際のコードが食い違っていたら、黙って合わせず報告すること
- 思いついた改善は実装せず、最終報告の末尾に「提案」として分離して書くこと
